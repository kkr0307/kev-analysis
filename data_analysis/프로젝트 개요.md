# 프로젝트 개요

## 목적

- NVD CVE와 CISA KEV를 활용한 취약점 특징·동향 분석
- 기간별 취약점 공개 현황과 CWE 유형 분포 확인
- 실제 악용이 확인된 취약점의 공통 특징 파악

## 1. 데이터 수집

| 데이터 | 수집 대상 | 용도 |
| :--- | :--- | :--- |
| NVD CVE | 분석 기간 내 공개된 CVE 상세 정보 | 공개일, 유형, 심각도 확인 |
| CISA KEV | 수집 시점의 전체 카탈로그 | 실제 악용 확인 목록과 대조 |

- 분석 기간: 데이터 규모 확인 후 확정
- NVD: 공개일 범위 지정, 해당 기간의 전체 페이지 수집
- KEV: 전체 목록 수집 후 CVE ID로 연결
- 저장: 원본 JSON 보관, 추출 결과 별도 저장
- 기록: 출처, 수집일, 조회 기간, 수집 건수
- CWE: NVD에 포함된 코드 활용

## 2. 데이터 추출

| 추출 항목 | 출처 필드 | 용도 |
| :--- | :--- | :--- |
| CVE ID | NVD `id` / KEV `cveID` | 데이터 연결 기준 |
| 공개일 | NVD `published` | 기간별 공개 현황 |
| 수정일 | NVD `lastModified` | 정보 갱신 시점 확인 |
| CWE 코드 | NVD `weaknesses[].description[].value` | 약점 유형 분류 |
| KEV 등재 여부 | CVE ID 일치 여부로 생성 | 등재·미등재 구분 |
| KEV 등재일 | KEV `dateAdded` | 등재 추이, 공개 후 등재까지의 간격 |
| 제조사·제품 | KEV `vendorProject`, `product` | KEV 내 대상별 분포 |
| CVSS 점수·버전·평가 출처 | NVD `metrics` | 심각도 비교용 보조 항목 |
a
### 정리 기준

- CVE ID 기준 중복 확인
- 날짜 형식과 집계 기준 통일
- CWE 누락·미분류 값 별도 구분
- 복수 CWE 모두 보존, 동일 CVE의 같은 CWE는 중복 집계 제외
- CVSS 평가가 여러 개면 출처 보존, 분석용 점수 선택 기준 명시

## 3. 분석 방향

| 분석 항목 | 확인할 내용 |
| :--- | :--- |
| 공개 추이 | 월별 CVE 공개 건수 변화 |
| 유형 분포 | CWE별 건수·비중, 기간별 변화 |
| KEV 비교 | 동일 공개 기간의 CVE 중 KEV 등재 비율, 유형별 차이 |
| 등재 추이 | KEV 등재일 기준 월별 추가 건수 |
| 대상 분포 | 제조사·제품별 KEV 등재 건수 |
| 심각도 비교 | KEV 등재·미등재 취약점의 CVSS 분포 |
| 등재 간격 | CVE 공개일부터 KEV 등재일까지의 기간 |

## 4. 분석 시 기준

- 공개일 기준 분석과 KEV 등재일 기준 분석 구분
- KEV 등재 비율 = 대상 CVE 중 KEV 등재 CVE 수 / 대상 CVE 수
- 전체 KEV 등재 추이·간격 분석에는 과거 공개 CVE도 포함
- CWE별 집계는 고유 CVE 수 기준, 복수 유형 때문에 유형별 합계가 전체 CVE 수를 넘을 수 있음
- CVSS는 같은 버전끼리 비교
- 취약점 건수와 실제 공격 횟수 구분
- KEV 미등재를 '악용 없음'으로 해석하지 않음
- KEV 등재일을 최초 악용일로 해석하지 않음

## 5. 진행 순서

1. 분석 기간·수집 범위 확정
2. NVD·KEV 원본 수집
3. 필드 추출·결측값 확인
4. CVE ID 기준 데이터 연결
5. 기간별·유형별 집계
6. 그래프 작성·결과 해석
