CVE-2026.json 분석

파일의 맨 위에서부터 읽으면 해당 파일 자체의 메타 데이터가 존재.
눈여겨 볼 것은 vulnerabilities라고 "취약점"들을 모아놓은 리스트임.

취약점(CVE)들에서 주로 살펴볼 값들은 다음과 같다.
- [cve] [id] : CVE 식별자. 유일해서 다른 DB에서 조회했을 때 동일한 취약점이 나온다.
- [cve] [published] : 취약점이 공개된 날짜
- [cve] [lastModified] : 취약점에 대한 정보가 마지막으로 업데이트 된 날짜

- [cve] [weakness] : 취약점의 유형이 어떤건지 담은 정보
- [cve] [weakness] [description] [value] : CWE 코드

=== CWE 코드 ===
이 취약점이 어떤 유형인지 세분화해둔 코드
예시) CWE-89 | SQL injection

## NVD CVE

| 컬럼명(임의) | NVD JSON 접근 경로 | 데이터 타입 | 설명 및 비고 |
| :--- | :--- | :--- | :--- |
| `cve_id` | `item["cve"]["id"]` | String | CVE 식별자 |
| `published` | `item["cve"]["published"]` | String | 취약점 최초 공개 일시 (YYYY-MM-DD) |
| `last_modified` | `item["cve"]["lastModified"]` | String | 취약점 정보 마지막 수정 일시 |
| `cwe` | `item["cve"]["weaknesses"][0]["description"][0]["value"]` | String | CWE 유형 코드 (예: CWE-89) |

## CISA KEV

| 컬럼명(임의) | CISA KEV JSON 접근 경로 | 데이터 타입 | 설명 및 비고 |
| :--- | :--- | :--- | :--- |
| `cve_id` | `item["vulnerabilities]["cveID"]` | String | 실제 악용이 확인되어 KEV에 등재된 취약점의 CVE 식별자. NVD의 `cve_id`와 연결하여 KEV 등재 여부 확인 |

출처: [CISA KEV 공식 JSON 스키마](https://github.com/cisagov/kev-data/blob/develop/known_exploited_vulnerabilities_schema.json)


=== CVE를 평가하는 지표 === 
1. CVSS
cvssMetricV{숫자} 식으로 기재되어있음.
- cvssMetricV40 : cvss v4.0 버전의 지표.
- cvssMetricV30 또는 cvssMetricV31 : cvss v3.x 버전의 지표들. 뒤져보니 3.0 아니면 3.1 밖에 없는 듯 하다.
- cvssMetricV2 : cvss v2.0 버전 지표
버전이 높을 수록 더 높은 정확도를 가진다. (cvss v4.0이 가장 높음)

2. SSVC
ssvcV203 밖에 찾지 못함.
CISA 에서 평가해서 제공해주는 지표라고 한다.
